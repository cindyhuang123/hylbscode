# 发布说明提炼

**用户视角转译，不是 commit 清单；破坏性变更置顶。**

## Procedure
1. 圈定范围：上一个 tag 到当前（`git log v1.2.0..HEAD`）。
2. 收集素材：用 Git 读提交与关键 diff；已有 changelog-miner 结果则直接复用。
3. 分组：**破坏性变更（置顶）** → 新特性 → 改进 → 修复 → 已知问题。
4. 转译：把 commit 原文改写成用户能懂的话（讲效果，不讲实现）；跳过 chore / docs 等无用户价值项。
5. 补充升级指引：配置变更、需要用户手动完成的步骤。

## 输出模板
```markdown
# <产品> <版本> (YYYY-MM-DD)
## 破坏性变更
## 新特性
## 改进
## 修复
## 升级指引
```

## 禁止
- 不许编造范围之外的改动；每条都要有对应提交。
- 不许把内部实现细节原样堆砌；每条都要有用户价值表述。
