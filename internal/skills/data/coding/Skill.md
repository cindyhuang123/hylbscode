# 编码工作流

**改动前先读，动手前先想清楚影响面。**

## 定位阶段（先探后动）
1. 不确定文件名/定义位置 → 用 Grep 搜关键词、函数名、类名。
2. 知道路径但不确定结构 → 用 Ls 看目录。
3. 已确定路径 → 用 View 读具体文件，别用 Grep / agent 绕。
4. 需要全局搜索同一符号跨库 → 先 Sourcegraph 再决定。

## 改动阶段
5. 小改动用 Edit（做精准文本替换）；新增/整体重写用 Write。
6. 改 Go 代码务必：改完 `go build` / `gofmt`，再跑相关单测（本项目 `go test ./internal/...`）。
7. 涉及多文件时，先列出改动清单，一次只改一个文件，保持编译通过。

## 提交规范
8. commit 用英文，格式 `feat: xxx` / `fix: xxx`，提交前先 `git status` 确认范围，**必须经用户确认再 commit**。

## 禁止
- 不要改写用户没提到要动的代码。
- 不要用 agent 子代理替代直接读写文件（慢且费 token）。
