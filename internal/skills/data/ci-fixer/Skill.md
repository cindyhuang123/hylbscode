# CI 修复（复现 → 根因 → 最小修复）

**先复现，再定位根因；只做让流水线转绿的最小改动。**

## Procedure
1. 复现：本地跑同一条失败命令（`go test ./...`、`npm test`、`make ci` 等），拿到与 CI 一致的报错输出。
2. 定位：读第一处失败（编译错误 / 失败断言 / 超时），用 Grep / View 找到源码位置与直接原因。
3. 修复：只改导致失败的最小范围；改 Go 代码后跑 `go build ./...`。
4. 验证：本地重跑同一命令必须通过；再跑相邻测试确认无连带破坏。
5. 汇报：改动文件 + 根因一句话 + 验证命令的实际输出。

## 输出模板
```markdown
## CI 修复记录
- 失败命令: <command>
- 根因: <一句话>
- 改动: <file:line → 做了什么>
- 验证: <通过的命令与结果>
```

## 禁止
- 不许删除测试、放宽断言、加 skip 来掩盖失败。
- 不许改 CI 配置（`.github/`、`.gitlab-ci.yml` 等）绕过检查。
- 不许提交未在本地验证通过的修复。
