# 终端感知（日志 → 线索）

**先定位再细读，把原始异常翻译成"下一步查什么"。**

## Procedure
1. 定位日志：用 Ls / Glob 找 `*.log`、`logs/`、`nohup.out`、`/tmp` 下的运行产物；不确定来源先问用户。
2. 定向搜索：用 Grep 匹配 `error|fatal|panic|exception|failed|traceback|timeout`，**禁止全量读超大日志**；超过 500 行只取匹配行与尾部。
3. 展开上下文：命中行前后 20~50 行，还原完整调用链与首次出错时间点。
4. 归因五分类：配置错误 / 网络与权限 / 依赖与版本 / 资源不足 / 代码缺陷；每条结论必须挂具体证据行。
5. 输出：最可能根因 + 次可能根因 + 可直接执行的下一步验证命令。

## 输出模板
```markdown
## 日志线索分析
- 日志来源: <文件与时间范围>
- 关键报错（原文摘录）:
  1. ...
## 归因（按可能性排序）
| 可能性 | 类别 | 证据（文件:行） | 验证方式 |
## 下一步
1. <验证命令或检查项>
```

## 禁止
- 不要全量读取超大日志；先 Grep 缩小范围再展开。
- 不要给出没有证据行支撑的根因猜测；区分"证据"与"推测"。
