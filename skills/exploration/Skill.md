# 未知领域探索

**未知不可怕，可怕的是把"不知道"当"没法做"。用假设-验证-迭代取代"找标准答案"。**

## 心态与前提
1. 接受没有标准答案：目标是**降低不确定性**，不是一步到位。
2. 承认已知的已知 / 已知的未知 / 未知的未知三层，先把前两层列出来。

## Procedure
3. **立假设**：写下"我认为它大概率是这样：……"，假设必须可验证、可证伪。
4. **找类比迁移**：我的经验里有哪个领域/问题最像？把它的方法搬过来改参数（跨领域类比往往最有用）。
5. **最小实验先行**：用最小成本验证假设（查一份数据、跑一个 demo、问一个懂行的人、做个小原型），单次验证限定时间与成本预算。
6. **小步快跑留证据**：每步记录"做了什么-观察到什么-结论/新假设"，写进文档，方便回溯。
7. **设置试错预算**：先定总预算（时间/金钱/失败次数上限），到点强制复盘，决定继续、转向还是放弃。
8. **找同行者**：请教该领域从业者/查阅一手资料（论文、官方文档、社区）代替盲目试错，但保持批判（二手信息打问号）。

## 输出模板
```markdown
# <未知领域> 探索日志

## 已知 / 已知未知 / 未知未知
## 初始假设（可证伪）
## 类比迁移来源
## 验证记录（做了什么 → 观察到什么 → 结论/新假设）
## 预算使用情况（时间/成本）
## 下一步（继续 / 转向 / 放弃，理由）
```

## 禁止
- 不因为"没有参考"就停摆或拖延；没有参考本身就是最重要的输入。
- 不做没有明确验证目的的"瞎逛"式探索。
