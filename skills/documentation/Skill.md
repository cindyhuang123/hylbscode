# 文档撰写

**先问读者是谁、文档干什么用，再动笔；文档要与代码同步维护。**

## 准备
1. 用 Grep / Ls 摸清项目现有文档结构，遵循已有风格，别另起炉灶。
2. 确认读者画像：入门用户 / 日常开发者 / 运维 / 审核方？不同读者结构和详略完全不同。

## Procedure
3. 先列大纲再写内容；结论和快速上手放最前面。
4. 每个代码示例必须是可运行的（能跑的通命令、能 build 的代码），别贴想象代码。
5. 说明版本/环境前提（依赖、OS、JDK/Node 版本等），标注变更记录（- 日期 - 改了什么）。
6. 注释规范：解释"为什么"而不是复述"做了什么"；公共 API 必须有导出注释。

## 输出模板
```markdown
# <项目/模块名>

## 简介（一句话说明它解决什么问题）
## 快速开始（3 步内跑起来）
## 配置与依赖
## 常用用法 / 示例
## 架构说明（必要时）
## 变更记录
```

## 禁止
- 不写过期内容；改代码必须同步改文档。
- 不贴未验证的示例。
